## 1. ЦЕЛЬ

Локальное офлайн-приложение-наставник для одного человека (владелец полигона),
которое тренирует не память на команды, а цикл принятия решений специалиста
(Red Team, Blue Team, DFIR) на собственном стенде `192.168.10.10`
(WebGoat, Juice Shop), принимает реальный вывод команд из терминала
пользователя, требует его собственной интерпретации до выдачи подсказки и
планомерно снижает объём подсказок от повтора к повтору.

Не входит в цель: быть справочником, быть каталогом лабораторных, быть
фреймворком эксплуатации.

## 2. ЧАСТИ СИСТЕМЫ

| Часть | Зачем |
|---|---|
| `server.py` (Python stdlib) | Отдаёт статику, читает и пишет состояние, проверяет доступность полигона, парсит вставленный вывод. Нужен потому, что браузер из-за CORS не отличает «сервис лежит» от «сервис ответил без нужных заголовков». |
| `web/` (vanilla JS, ES-модули) | Экраны: Today, Lab Runner, Range, Playbook, Reference, Notes, Progress. Без сборщика и без node_modules. |
| `content/` (JSON + Markdown, в git) | Треки, лаборатории, шаги, playbooks, команды, глоссарий. Контент это данные, не код и не документы. |
| `state.sqlite` | Попытки, наблюдения, заметки, уровни навыков, очередь повторения, история статуса полигона. |
| `parsers/` | Правила извлечения фактов из вставленного вывода (`nmap`, `curl -i`, HTTP-ответ, лог). Регулярные выражения, без ИИ. |
| `mentor/` | Правила сверки вывода пользователя с рубрикой шага. Версия 1 без модели. |
| `start.command` | Двойной клик в Finder поднимает сервер и открывает `http://127.0.0.1:8899/`. |

## 3. ВХОД → ВЫХОД КАЖДОЙ ЧАСТИ

**server.py**
- Вход: HTTP-запросы фронта; файлы `content/`; `state.sqlite`.
- Выход: JSON API и статика.
- Контракты:
  - `GET /api/today` → `{track, lab, step, assistance_level, review_due[]}`
  - `GET /api/lab/{id}` → лаборатория со скрытыми полями (`solution`, `hints` не отдаются, пока не запрошены явно)
  - `POST /api/attempt` `{lab_id, step_id, hypothesis}` → `{attempt_id}`; без гипотезы шаг не открывает команду
  - `POST /api/attempt/{id}/output` `{raw}` → `{facts[], unparsed[], parser}`
  - `POST /api/attempt/{id}/conclusion` `{text}` → `{feedback[], missed[], verdict}`
  - `GET /api/hint/{lab}/{step}?level=1|2|3` → один уровень подсказки, факт запроса пишется в попытку
  - `POST /api/attempt/{id}/decision` `{choice}` → `{correct, why, next_step}`
  - `GET /api/range/health` → `{host, checks[], verdict, diagnosis[]}`
  - `GET|POST /api/notes`, `GET /api/progress`

**parsers**
- Вход: сырой текст, подсказка о типе (`nmap|curl|http|log|auto`).
- Выход: `facts[] = {kind, value, source_line}` и остаток `unparsed[]`.
- Правило: парсер извлекает только то, что буквально есть в тексте. Он не достраивает и не угадывает. Всё, что не разобрано, показывается пользователю как есть.

**mentor (v1, без модели)**
- Вход: `facts[]`, текст вывода пользователя, рубрика шага (`expect[]`, `distractors[]`).
- Выход: список «ты назвал», «ты пропустил», «это гипотеза, а не факт», наводящий вопрос.
- Правило: наставник не выдаёт решение. Он сравнивает и спрашивает.

**range health**
- Вход: `192.168.10.10`, порты 8080 и 3000.
- Выход: лестница проверок TCP → HTTP-код → признак содержимого, плюс адресная диагностика при отказе.

## 4. ДАННЫЕ

Разделение принципиальное: **контент в файлах под git, состояние в SQLite**.

**Контент (`content/`, JSON и Markdown, редактируемо руками и генерируемо Codex)**
- `tracks/*.json`: `{id, role, title, goal, skill_ids[], lab_ids[]}`
- `skills/*.json`: `{id, title, role, prereq_ids[], mastery_criteria}`
- `labs/*.json`: `{id, track_id, role, mission, objective, known[], skills[], steps[]}`
- `steps` внутри лабы: `{id, kind: think|execute|analyse|decide|debrief, prompt, why, command, command_anatomy[], expect[], distractors[], parser, hints[3], solution, decision_options[]}`
- `playbooks/*.json`: `{id, role, title, phases[{id, title, checks[], decision{question, branches[]}}]}`
- `commands/*.json`: `{id, name, purpose, syntax, args[], when, when_not, look_for[], example_output, mistakes[], next_steps[]}`
- `glossary/*.json`: `{term, plain_meaning, where_you_meet_it, related[]}`

**Состояние (`state.sqlite`)**
- `attempt(id, lab_id, step_id, ts, hypothesis, raw_output, user_conclusion, hints_used, revealed_solution, decision_choice, verdict)`
- `observation(id, attempt_id, kind fact|hypothesis, text, source_line)`
- `note(id, lab_id, date, goal, hypothesis, commands, results, conclusion, mistakes, learned)`
- `skill_progress(skill_id, level 0..5, assistance_level 0..4, last_seen, next_review)`
- `review_queue(skill_id, due_date, reason)`
- `range_check(ts, host, port, ok, detail)`

Поиск по словам (SQLite FTS5 по командам, глоссарию и заметкам). Семантический
поиск не нужен: корпус свой и небольшой.

## 5. СЦЕНАРИИ

1. **Первый шаг разведки.** Открыл сайт → Today показывает одну карточку «Трек 1, лаба 2, шаг 1» → Range сверху зелёный → экран требует гипотезу «что я узнаю этой проверкой» → только после ввода открывается команда `nmap -sV 192.168.10.10` с разбором аргументов → выполнил в своём Terminal → вставил вывод → парсер выделил порты, сервисы, версии как факты → написал свой вывод → наставник сказал, что пропущено и что было гипотезой, а не фактом → развилка «куда дальше» с двумя вариантами и обоснованием → шаг закрыт, попытка и артефакт легли в Field Notes.

2. **Тот же навык во второй раз.** Через несколько дней Today выдаёт лабу на том же навыке, но `assistance_level` уже ниже: «зачем» скрыто за кнопкой, команда не показана, есть только цель. Пользователь вспоминает сам, при необходимости берёт подсказку 1 (направление). Уровень навыка растёт только если решение принято без раскрытия solution.

3. **Полигон недоступен.** Range показывает красный на порту 3000 → сайт не пускает в лабу Juice Shop, а даёт лестницу диагностики: TCP до 8080 проходит, значит хост жив и IP верный, значит дело в самом приложении Juice Shop, а не в сети → конкретный шаг на Windows-машине.

4. **Blue-разворот одного артефакта.** Тот же HTTP 401 из шага Red открывается в режиме Blue: «это нормальная ошибка входа или перебор». Роль явно меняется в шапке и цветом, вопросы другие, playbook другой, навык засчитывается отдельный.

## 6. НЕ-ЦЕЛИ ЭТОЙ ВЕРСИИ

- Никакого автоматического сканирования, эксплуатации или отправки нагрузок из приложения. Команды выполняет человек в своём терминале.
- Нет мультиюзера, аккаунтов, облака, синхронизации между машинами.
- Нет ИИ-наставника в версии 1. Рубрика и парсер закрывают обратную связь без модели.
- Нет мобильной версии и нет PWA.
- Нет переноса всех 77 уроков RED & BLUE CYBER PILL. Он остаётся отдельным сайтом-справочником, из него берутся только те темы, под которые написан трек.
- Нет модуля Robotics/Drones. Он отложен и в MVP не проектируется.
- Нет автоматической проверки флагов и скоринга как в CTF.

## 7. ДОСТУПЫ ОТ ЧЕЛОВЕКА

- Windows-полигон должен быть включён и держать `192.168.10.10`. Проверить и при необходимости закрепить статический IP или DHCP-резервацию может только пользователь.
- Разрешение Windows Firewall на входящие 8080 и 3000 в локальной сети.
- Явное «go» на установку любых зависимостей. Проект спроектирован так, чтобы их не потребовалось: только системный `python3` из macOS.
- Явное «go» на создание git-репозитория и приватный push.
- Если позже включаем ИИ-наставника: решение об использовании подписки (`claude -p`), а не метрического API-ключа, принимает пользователь.

## 8. ГОТОВО-КОГДА

Версия 1 считается готовой, когда все пункты проверяемы фактом:

1. `./start.command` поднимает сайт на `http://127.0.0.1:8899/` на чистом Mac без установки пакетов.
2. `GET /api/range/health` возвращает верный вердикт в трёх состояниях: оба сервиса живы, один лежит, хост недоступен. Проверено выключением Juice Shop.
3. Экран лаборатории физически не показывает команду, пока не сохранена гипотеза, и не показывает solution, пока не запрошены три подсказки или не отправлен собственный вывод.
4. Вставка реального вывода `nmap -sV 192.168.10.10` даёт список портов, сервисов и версий, совпадающий с текстом построчно, а неразобранные строки показаны честно.
5. Наставник на реальном выводе называет минимум один пропущенный признак из рубрики и минимум одну гипотезу, поданную как факт.
6. Полный проход трека 1 из 6 лабораторий сохраняет 6 записей в Field Notes и поднимает уровни соответствующих навыков.
7. Повторная выдача того же навыка приходит на уровень ниже по подсказкам, что видно в интерфейсе и в `skill_progress`.
8. Перезапуск сервера и перезагрузка Mac не теряют прогресс: состояние в файле `state.sqlite`, а не в localStorage.
9. Чек-лист методического качества (15 пунктов, `blueprint.md`) пройден для каждой лаборатории трека 1.
10. Ни один экран не показывает больше одного основного действия, проверено визуально на ширинах 1280 и 1680.
