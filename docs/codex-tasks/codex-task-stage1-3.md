ЭТАП 1. Foundation
- Структура: server.py, web/, content/{tracks,skills,labs,playbooks,commands,glossary}/, tools/, start.command
- server.py: ThreadingHTTPServer на 127.0.0.1:8899, раздача статики из web/, роутинг /api/*.
- start.command: двойной клик в Finder поднимает сервер и открывает http://127.0.0.1:8899/. Если порт занят этим же сайтом, просто открыть страницу. Если занят чужим процессом, выйти с понятным сообщением и НЕ убивать чужой процесс. Права на исполнение выставить (chmod +x).
- Проверяемый результат: запуск открывает страницу, ноль установок.

ЭТАП 2. Data model
- Схема SQLite по разделу 4 spec.md: attempt, observation, note, skill_progress, review_queue, range_check. База создаётся при первом запуске, если её нет.
- Инварианты из blueprint.md раздел H: attempt неизменяема после закрытия шага; observation.kind принимает только 'fact' или 'hypothesis' (CHECK-констрейнт в схеме).
- Загрузчик content/: читает JSON, отдаёт в API. Поля лабы и шага строго по spec.md раздел 4.
- tools/validate_content.py: проверяет схему всех JSON в content/, ссылочную целостность (prereq_ids, skill_ids, lab_ids существуют), обязательные поля шага, ровно 3 подсказки там, где они есть. Ненулевой код возврата при ошибке.
- Демонстрационный контент: один трек, два навыка, одна лаба с 5 шагами по образцу «Lab 1.2 Service enumeration» из blueprint.md раздел M. Текст брать из blueprint.md дословно, свой не выдумывать.
- Проверяемый результат: python3 tools/validate_content.py проходит с кодом 0, пустая база создаётся при первом запуске.

ЭТАП 3. Range health
- GET /api/range/health, лестница по blueprint.md раздел J: 1) TCP connect 192.168.10.10:8080 таймаут 1.5с 2) TCP connect :3000 таймаут 1.5с 3) HTTP GET /WebGoat/ на 8080, ожидаем 200 или 302 4) HTTP GET / на 3000, ожидаем 200 и признак содержимого.
- Ответ {host, checks[], verdict, diagnosis[]} с адресной диагностикой по таблице раздела J: оба порта закрыты = хост недоступен или firewall; 8080 жив, а 3000 нет = лежит конкретно Juice Shop; порт открыт, но код неожиданный = сервис поднялся не полностью.
- Каждая проверка пишется в таблицу range_check.
- Экран Range в web/: статус ONLINE/OFFLINE по каждому сервису, кнопки Open для WebGoat и Juice Shop, лестница диагностики при отказе. Тёмная спокойная тема, крупная типографика, хорошая читаемость, один основной блок на экране. Без Matrix rain, без неона, без декоративных терминалов.
- Проверяемый результат: при недоступном 3000 диагностика адресная («лежит Juice Shop»), а не общая «ошибка».
