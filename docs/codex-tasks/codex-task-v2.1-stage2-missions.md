ЭТАП 2, пункты:

1. Модель миссии (контент под git, YAML в curriculum/, стиль как linux-techniques.yaml).
- Mission: устойчивый id, заголовок, сюжет, разрешённая среда, подготовленные синтетические данные (описание набора файлов/строк), проверяемые действия, конечный артефакт (что считается решением), связь с приёмами (technique_ids из Этапа 1), варианты повтора (как меняются имя/расположение/содержимое), версия.

2. Mission grader (версия 1), отдельный модуль, не grader.py и не recall_grader.py.
- Вход: заявленный ответ ученика (найденная строка/файл/значение) + объяснение + контракт миссии. Ничего не исполняется.
- Проверяет ФИНАЛЬНЫЙ артефакт детерминированной проверкой результата (точное или regex-совпадение с ожидаемым, заданным в контракте миссии) плюс объяснение через существующий механизм наблюдения (переиспользовать grade_observation из recall_grader или аналог).
- Заявленные корректные варианты (несколько допустимых решений) допускаются из контракта. Поддельный/выдуманный вывод не принимается. Неизвестный вариант возвращает статус «нужна проверка» (needs_review), а не ложный успех.
- Выход: различимый статус (solved | wrong_artifact | unexplained | needs_review) с причиной.

3. MissionRun (SQLite, аддитивно).

4. Два сценария-миссии (обезличенный синтетический контент).
- «Сорока: пропавшая улика»: подготовленный каталог из нескольких синтетических файлов и один полезный след. Нужно найти файл, выбрать строку и объяснить её связь с задачей. Используются встречавшиеся в Linux 01-04 приёмы pwd, ls, cd, find, file, cat, grep, cut по мере задачи. На повторе меняются имя файла, расположение и содержимое, цель узнаваема. Успех зависит от найденного результата и объяснения, а не от воспроизведения старого флага.
- «Почему команда не сработала»: показана короткая команда и наблюдаемый ответ с намеренной ошибкой в синтетических учебных данных. Нужно определить и исправить причину. Типовые путаницы: имя против содержимого, текущая против постоянной переменной, CMD против Linux shell, флаг против аргумента. Объяснение раскрывается только после ответа. Случайный выбор варианта не считается самостоятельным вводом.
