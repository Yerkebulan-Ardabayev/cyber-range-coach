## Ошибка 1: Ubuntu засыпает, SSH из академии получает отказ (важно)

Что делал: мастер прошёл в видимом окне Ubuntu. Окно закрыли, через минуту нажал «Проверить SSH».
Текст на экране: `TCP-СОЕДИНЕНИЕ НЕ УСТАНОВЛЕНО: CONNECTIONREFUSEDERROR`.
Причина: когда в Ubuntu не остаётся процессов, запущенных через `wsl.exe`, WSL останавливает дистрибутив через несколько секунд
(`wsl -l -v` → `Ubuntu Stopped`), несмотря на systemd и включённый ssh. TCP-подключение на 127.0.0.1:22 WSL не будит.
После любого `wsl.exe …` порт 22 снова открыт, и проверка SSH прошла.
Затем то же случилось на «Проверить range-runner»: `POST /api/v2/system/linux-host/1/runner-check HTTP/1.1" 503` в 15:11:49
(в 15:11:23 подключение range-runner при подтверждении отпечатка прошло, через 24 с Ubuntu уже спала). На экране при 503 **не
появилось никакого сообщения**, кнопка просто ничего не показала.
Обход для проверки (настройки не менял): скрытый процесс `wsl.exe -d Ubuntu -- sleep infinity`, после него всё прошло с первого раза.
Предложение для Mac: академия перед SSH (probe, runner-check, открытие lab) будит дистрибутив, например `wsl.exe -d <distro> --exec true`,
и держит его, пока открыта лаба (фоновый `wsl.exe … sleep`), или при ConnectionRefused на 127.0.0.1 сама делает одну попытку разбудить и повторить.
Плюс показывать ошибку runner-check на экране.

## Ошибка 2: подсказка сверки отпечатка не совпадает с показанным ключом

Сайт просит сверить с `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`, а показывает отпечаток RSA-ключа:
- на сайте: `SHA256:JdZfrkD9/W9GiGd5bh+7FxPQN5LTAADezVK+3OQmZoI`
- ED25519 в Ubuntu: `SHA256:dDXxTIiiOxPKlAApHoTMiX0WmeslULw+3/IibRrjtDk` (не совпадает)
- RSA в Ubuntu: `SHA256:JdZfrkD9…` (совпадает, `ssh-keyscan 127.0.0.1` то же)
Владелец по подсказке решит, что ключ подменён. Нужно либо предпочитать ssh-ed25519 в asyncssh (`server_host_key_algs`),
либо показывать тип ключа и верную команду сверки. Я подтвердил, потому что RSA-ключ сервера совпал.
