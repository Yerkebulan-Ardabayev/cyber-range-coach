## Ошибка 1 (решена с разрешения владельца): `student` уже был в Ubuntu

Что делал: «Система» → «Подготовить WSL Ubuntu», затем в окне Ubuntu показанная команда
`sudo bash .../bootstrap-wsl-ubuntu.sh --approve-install --student-user student --runner-user range-runner ... --relay-host 172.30.160.1`
(sudo-пароль вводил владелец).

Текст: `Существующий пользователь student не принадлежит Cyber Range Coach, изменение запрещено.` (exit 73)

До этого в Ubuntu был `student` (uid 1001, GECOS `,,,`, группы student, users, без sudo), создан не мастером.
Владелец разрешил отдать его мастеру: `sudo usermod -c "Cyber Range Coach" student`.
Замечание для Mac: `chfn -f` не годится, он оставляет GECOS `Cyber Range Coach,,,`, и проверка
`!= "Cyber Range Coach"` снова отказывает. Мастер мог бы подсказывать владельцу, как поступить в этом случае.

## Ошибка 2 (не решена, баг в коде): ложное «правило sudo» для student

Текст: `Небезопасная настройка остановлена: для student найдено правило sudo.` (exit 78)

Причина: `bootstrap-linux.sh` строка 101:
```
if sudo -n -l -U "$student_user" >/dev/null 2>&1; then
```
В sudo 1.9.15p5 (Ubuntu) `sudo -l -U` возвращает **exit 0**, даже когда у пользователя нет прав. Проверка от root:
```
== sudo -n -l -U student
User student is not allowed to run sudo on Yerkebulan.
exit=0
== sudo -n -l -U range-runner
User range-runner is not allowed to run sudo on Yerkebulan.
exit=0
```
sudoers чистый: `root`, `%admin`, `%sudo`, `@includedir /etc/sudoers.d`, в sudoers.d только README.
`student` не в группах sudo и admin (`sudo:x:27:ye`, `admin:x:106:`). Значит, мастер остановится на любой
машине с таким sudo, даже с новым `student`. Предлагаю проверять вывод, а не код возврата: например, считать правило найденным,
только если вывод не содержит `is not allowed to run sudo`, или разбирать строки после `may run the following commands`.
Нужен тест с заглушкой sudo, которая возвращает 0 и печатает «not allowed».

Журнал сайта (`%LOCALAPPDATA%\CyberRangeCoach\logs\academy.log`): prepare прошёл без ошибок,
`POST /api/v2/system/linux-host/1/wsl-ubuntu/prepare HTTP/1.1 200` в 14:10:13. Ошибка возникает только внутри Ubuntu.
Там же есть шум `ConnectionResetError: [WinError 10054]` в `_ProactorBasePipeTransport._call_connection_lost`
(asyncio на Windows), на работу не влияет.
